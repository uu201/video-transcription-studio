## 1. 开发目标

本文档用于指导第一版本地应用开发，目标是先完成一条稳定的可操作链路：

```text
启动 Python 应用
    ↓
浏览器打开操作界面
    ↓
配置本地输入目录
    ↓
扫描视频和音频
    ↓
创建 SQLite 任务
    ↓
Worker 读取任务
    ↓
内置 FFmpeg 提取音频
    ↓
独立 SenseVoiceProvider 转写
    ↓
保存文本、JSON、时间戳和任务事件
    ↓
界面查看和导出
```

AI 总结、文件归档和移动在同一条任务流水线上预留接口，但应在 ASR 主流程稳定后接入。

## 2. 已确定的技术决策

### 2.1 后端和界面

```text
后端：Python
Web：FastAPI + Uvicorn
页面：Jinja2 + HTMX + 原生 JavaScript
数据库：SQLite
后台任务：独立 Python Worker
```

MVP 不采用 Vue、Redis、Celery 或微服务。后续如页面复杂度提升，可以只替换界面层。

### 2.2 ASR 关系

```text
QwenAudio/SenseVoice
    = SenseVoice 官方仓库、代码和示例参考

SenseVoiceSmall
    = 实际使用的 ASR 模型

FunASR
    = Python 推理框架、模型加载和长音频处理框架

FSMN-VAD
    = 语音活动检测和音频分段模型
```

正式后端使用：

```text
FunASR + iic/SenseVoiceSmall + fsmn-vad
```

参考资料：

- [QwenAudio/SenseVoice](https://github.com/QwenAudio/SenseVoice)
- [FunASR](https://github.com/modelscope/FunASR)
- [SenseVoice 中文说明](https://github.com/QwenAudio/SenseVoice/blob/main/README_zh.md)

### 2.3 `video_to_text.py` 的边界

`video_to_text.py` 是独立的 CLI 参考工具，不是后端模块。

要求：

- 后端不得导入 `video_to_text.py`。
- Worker 不调用 `video_to_text.py` 的 `main()`。
- `app/services/asr/sensevoice_provider.py` 参考其流程重新编写。
- 后端使用自己的配置、日志、临时目录、错误类型和结果模型。
- CLI 和 Web 允许在参数上独立演进。

### 2.4 FFmpeg 的边界

正式应用内置 `ffmpeg` 和 `ffprobe`，不要求用户单独安装。

```text
runtime/
└── ffmpeg/
    ├── windows-x64/
    │   ├── ffmpeg.exe
    │   └── ffprobe.exe
    ├── linux-x64/
    │   ├── ffmpeg
    │   └── ffprobe
    └── macos-arm64/
        ├── ffmpeg
        └── ffprobe
```

代码只能通过 `MediaToolchain` 获取路径：

```python
toolchain = MediaToolchain.from_app_root()
toolchain.check()
ffmpeg = toolchain.ffmpeg_path()
ffprobe = toolchain.ffprobe_path()
```

开发时允许通过环境变量覆盖路径，生产包默认使用 `runtime/ffmpeg/`。

## 6. 核心接口

### 6.1 ASR 结果

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Any


@dataclass
class ASRSegment:
    sequence: int
    start: float
    end: float
    text: str
    speaker: str | None = None
    confidence: float | None = None


@dataclass
class ASRResult:
    language: str | None
    text: str
    segments: list[ASRSegment]
    raw_result: list[dict[str, Any]]


class ASRProvider:
    def transcribe(
        self,
        audio_path: Path,
        language: str,
        options: dict[str, Any],
    ) -> ASRResult:
        raise NotImplementedError
```

统一异常：

```python
class ASRError(Exception):
    code: str
    user_message: str
    detail: str | None
    retryable: bool
```

Provider 不负责写数据库、不负责导出文件、不负责更新任务进度，只负责将一个音频文件转换为 `ASRResult`。

### 6.2 `SenseVoiceProvider`

文件：

```text
app/services/asr/sensevoice_provider.py
```

内部实现要求：

1. 延迟导入 `funasr.AutoModel`，让 Web 首页在未安装模型依赖时仍可打开。
2. 使用配置加载 `iic/SenseVoiceSmall`。
3. 使用 `fsmn-vad` 和 `max_single_segment_time`。
4. 设置 `disable_pbar=True`、`disable_log=True`、`disable_update=True`。
5. 解析 FunASR 的列表或字典返回值。
6. 保存完整原始 JSON。
7. 将时间戳统一转换为秒。
8. 不打印模型内部进度条。
9. 将依赖错误、模型加载错误、推理错误转换为统一异常。

伪代码：

```python
class SenseVoiceProvider(ASRProvider):
    def __init__(self, settings: ASRSettings):
        self.settings = settings
        self._model = None

    def _load_model(self):
        if self._model is None:
            from funasr import AutoModel

            self._model = AutoModel(
                model=self.settings.model,
                trust_remote_code=True,
                vad_model="fsmn-vad",
                vad_kwargs={
                    "max_single_segment_time": (
                        self.settings.max_single_segment_time_ms
                    )
                },
                device=self.settings.device,
                disable_pbar=True,
                disable_log=True,
                disable_update=True,
            )
        return self._model

    def transcribe(
        self,
        audio_path: Path,
        language: str,
        options: dict,
    ) -> ASRResult:
        model = self._load_model()
        result = model.generate(
            input=str(audio_path),
            cache={},
            language=language,
            use_itn=options.get("use_itn", True),
            batch_size_s=options.get("batch_size_s", 30),
            merge_vad=True,
            merge_length_s=options.get("merge_length_s", 15),
        )
        return normalize_sensevoice_result(result)
```

以上为接口约束和实现方向，正式代码需要补齐时间戳字段兼容、异常分类和单元测试。

### 6.3 媒体工具接口

```python
class MediaToolchain:
    def ffmpeg_path(self) -> str:
        raise NotImplementedError

    def ffprobe_path(self) -> str:
        raise NotImplementedError

    def check(self) -> None:
        raise NotImplementedError
```

`audio_extractor.py` 和 `media_probe.py` 不允许调用 `shutil.which("ffmpeg")` 作为生产路径。

外部命令调用要求：

- 使用参数数组，不拼接 shell 字符串。
- 使用 `subprocess.run(..., shell=False)`。
- 设置超时、编码和最大错误输出长度。
- 临时文件使用任务专属目录，文件名不得直接信任用户输入。
- 命令失败转换为 `FFMPEG_FAILED` 或 `MEDIA_PROBE_FAILED`，并保留退出码。

```python
class LLMProvider:
```

## 7. 任务流水线实现

### 7.1 `PipelineService`

任务编排只依赖接口：

```text
PipelineService
    ├── MediaToolchain
    ├── MediaProbe
    ├── AudioExtractor
    ├── ASRProvider
    ├── TextProcessor
    ├── Exporter
    ├── LLMProviderFactory
    └── FileTransferService
```

伪代码：

```python
def process(task_id: int) -> None:
    task = task_repository.claim(task_id)

    update_stage(task, "PROBING", 5, "正在读取媒体信息")
    media_info = media_probe.inspect(task.media_file.path)

    update_stage(task, "EXTRACTING", 20, "正在提取音频")
    audio_path = audio_extractor.prepare(task.media_file.path)

    update_stage(task, "TRANSCRIBING", 70, "正在识别音频，请稍候")
    asr_result = asr_provider.transcribe(
        audio_path,
        task.language,
        task.asr_options,
    )

    update_stage(task, "POST_PROCESSING", 80, "正在整理文案")
    transcript = text_processor.process(asr_result)

    update_stage(task, "SAVING", 85, "正在保存转写结果")
    transcript_repository.save(task, transcript)
    exporter.export_all(task, transcript)

    if task.requested_ai:
        update_stage(task, "ANALYZING", 95, "正在进行 AI 分析")
        analysis_service.analyze(task, transcript)

    if task.transfer_policy != "keep":
        update_stage(task, "TRANSFERRING", 98, "正在处理文件归档")
        transfer_service.execute(task)

    task_repository.complete(task)
```

实际实现必须使用 `try/except/finally`：

- `try` 中执行阶段流程。
- 捕获 `AppError` 时保存用户提示、错误编码和可重试标记。
- 捕获未知异常时记录完整堆栈到文件，并向页面返回通用错误提示。
- `finally` 中删除任务临时目录，除非配置为保留调试产物。
- 每完成一个阶段，先提交数据库事件，再进入下一阶段。

阶段更新统一使用：

```python
progress_service.update(
    task_id=task_id,
    stage="TRANSCRIBING",
    progress=70,
    message="正在识别音频，请稍候",
)
```

进度由平台计算，不读取 FunASR 的 tqdm 输出。ASR 无法提供可靠百分比时，识别阶段显示固定阶段文案和已耗时。

### 7.2 幂等要求

- `PROBING` 可重复读取。
- 已存在且哈希一致的音频缓存可以复用。
- 已存在且版本一致的转写结果可以复用。
- AI 结果按转写版本、Prompt 版本、Provider 和模型判定是否复用。
- 文件转移按源哈希、目标路径和操作类型判定是否复用。

### 7.3 任务事件

每次阶段变化同时写入：

```text
processing_task
task_event
```

界面读取 `task_event`，不解析控制台日志。

### 7.4 恢复和取消

Worker 每次领取任务后写入 `worker_id` 和 `heartbeat_at`，长阶段按固定间隔更新心跳。

启动恢复规则：

```text
RUNNING 且 heartbeat_at 未超时
    → 保持运行状态，不重复领取

RUNNING 且 heartbeat_at 已超时
    → 写入恢复事件，创建新的重试任务或恢复为 QUEUED
```

取消规则：

- Web API 只写入 `cancel_requested = 1`，不直接终止模型线程。
- Worker 在阶段边界、外部命令返回后检查取消标记。
- 取消时保留已经生成的中间结果，并将未完成输出标记为临时文件。
- 取消动作写入 `task_event`，最终状态为 `CANCELED`。

## 8. SQLite 开发规范

### 8.1 建库


迁移文件使用递增版本号，例如：

### 8.3 事务边界

- 扫描文件和创建任务：一个事务。
- 领取任务：短事务，不能包住 FFmpeg 或模型推理。
- 阶段状态和事件：一个短事务。
- 转写结果和分段：一个事务。
- 文件操作完成后再写转移成功记录。

### 8.4 任务领取

使用条件更新或 SQLite 写事务保证同一任务只被一个 Worker 领取：

```sql
UPDATE processing_task
SET status = 'RUNNING',
    current_stage = 'PROBING',
    started_at = :now,
    updated_at = :now
WHERE id = :task_id
  AND status = 'QUEUED';
```

应用检查受影响行数：

```text
1 行 → 领取成功
0 行 → 任务已被其他 Worker 领取或状态不允许
```

SQLite 连接建议：

```text
PRAGMA foreign_keys = ON
PRAGMA journal_mode = WAL
PRAGMA busy_timeout = 5000
```

WAL 只用于提升 Web 查询和 Worker 写入同时发生时的可用性；每次事务仍应尽量短，不能把模型推理放进事务。

## 11. 日志和错误处理

### 11.1 日志

控制台日志由平台统一输出：

```text
12:00:01 | INFO    | 开始处理：example.mp4
12:00:02 | INFO    | 正在提取音频
12:00:05 | INFO    | 正在识别音频，请稍候
12:00:35 | INFO    | 识别完成：耗时 30.1 秒 | 12 段 | 356 字符
12:00:35 | INFO    | 已保存转写结果
```

禁止把以下内容直接展示给普通用户：

```text
rtf_avg
tqdm 进度条
模型 cache
完整 Python 堆栈
API Key
```

统一控制台格式：

```text
HH:mm:ss | LEVEL   | 任务 #123 | 阶段 | 人话消息
```

示例：

```text
11:28:37 | INFO    | 任务 #123 | 开始处理：example.mp4
11:28:42 | INFO    | 任务 #123 | 语音识别开始，请稍候
11:29:18 | SUCCESS | 任务 #123 | 处理完成：耗时 41.2 秒 | 12 段 | 1,256 字
```

实现要求：

- 使用 Python `logging`，控制台和文件使用不同 Handler。
- FunASR、ModelScope 和第三方库的普通日志降到 WARNING 或定向写文件。
- 禁用 tqdm 的终端输出，不能出现多行回刷进度条。
- 每个阶段最多输出开始和结果两条常规日志。
- 任务级详细过程写入 `task_event`，页面不解析日志文件。
- 日志文件按天滚动，保留天数可配置。

### 11.2 错误

所有异常转换为：

```python
from dataclasses import dataclass


@dataclass
class AppError(Exception):
    code: str
    user_message: str
    detail: str | None = None
    retryable: bool = False
    user_action: str | None = None
```

错误分类必须包含 `retryable` 和 `user_action`，例如：

```python
AppError(
    code="ASR_MODEL_LOAD_FAILED",
    user_message="语音识别模型加载失败",
    detail="...",
    retryable=True,
    user_action="检查模型目录或切换到 CPU 后重试",
)
```

示例：

```text
FFMPEG_NOT_FOUND
用户提示：应用内置媒体工具不可用，请重新安装或修复应用。
可重试：否
```

```text
ASR_MODEL_LOAD_FAILED
用户提示：语音识别模型加载失败，请检查模型文件和内存。
可重试：是
```

## 15. 常见问题处理

### 15.1 控制台出现 `rtf_avg` 或进度条

检查 `SenseVoiceProvider` 是否传入：

```python
disable_pbar=True
disable_log=True
disable_update=True
```

同时检查第三方 Logger 和 tqdm 是否通过根 Logger 或标准输出写入终端。平台自己的阶段日志必须保持可读。

### 15.2 1060 3 GB 显存不足

默认将 ASR 设备设为 `cpu`，Worker 并发设为 `1`，并将 `batch_size_s` 控制在 `30` 左右。GPU 只作为实验配置，不作为 MVP 的验收前提。

### 15.3 模型下载失败

页面需要区分“模型尚未下载”“模型下载失败”“模型加载失败”。记录模型目录、网络错误和重试建议，但不把完整访问凭证写入日志。

### 15.4 文件归档后找不到源文件

移动操作只有在目标文件大小和哈希校验成功后才能删除源文件。任何校验失败都必须保留源文件，并将 `file_transfer` 标记为 `FAILED`。
