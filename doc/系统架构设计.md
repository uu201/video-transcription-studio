# 视频文案提取与 AI 内容分析平台：系统架构设计

> 本文档定义系统边界和模块关系；具体实现步骤、代码接口和测试方法见《开发文档.md》。

## 1. 架构结论

项目采用本地部署的模块化单体架构：

```text
浏览器操作界面
        │
        ↓
FastAPI 本地 API / 页面服务
        │
        ├── SQLite：任务、结果、配置、历史记录
        ├── 本地文件系统：视频、音频、导出结果、归档文件
        └── Python Worker：扫描、转写、AI 分析、文件转移
                         │
        ├── 内置 FFmpeg / FFprobe
        ├── 独立 SenseVoice ASR Provider
        └── 可替换的 LLM Provider
```

默认访问地址：

```text
http://127.0.0.1:8000
```

### 1.1 选型

| 层级 | 技术 |
|---|---|
| 操作界面 | Jinja2 + HTMX + 少量原生 JavaScript |
| Web/API | Python + FastAPI + Uvicorn |
| 数据库 | SQLite |
| ORM/数据访问 | SQLAlchemy 2.x |
| 数据校验 | Pydantic |
| 后台任务 | 独立 Python Worker 进程 |
| 媒体处理 | 应用内置 FFmpeg / FFprobe |
| 语音识别 | FunASR 推理框架 + SenseVoiceSmall 模型 + FSMN-VAD |
| AI 分析 | 可插拔 LLM Provider |
| 结果导出 | Python 文件模块 |

### 1.2 为什么采用本地 Web 界面

- 用户需要操作界面，但核心数据和视频都在本机。
- FastAPI 可以同时提供页面和 API，部署简单。
- Jinja2/HTMX 足以完成目录配置、任务列表、进度刷新、结果查看和设置管理。
- 不需要浏览器把本地视频重新上传到服务器，后端直接读取用户配置的本机目录。
- 后续如果界面复杂度增加，可以将页面替换为 Vue，不影响后端 API 和 Worker。
- FFmpeg 和 FFprobe 随应用发布，不要求用户单独安装或配置系统 PATH。

> 浏览器出于安全限制不能直接把任意本地目录路径交给网页。MVP 使用“输入本机目录绝对路径”的方式配置扫描源；后续可以增加桌面壳和原生目录选择器。

## 2. 运行形态

### 2.1 MVP 进程

MVP 启动两个 Python 进程：

```text
start.py
   ├── web 进程：FastAPI + Uvicorn
   └── worker 进程：任务轮询和处理
```

Web 进程只负责：

- 页面渲染
- 接收用户操作
- 写入任务和配置
- 查询 SQLite
- 返回任务状态

Worker 进程负责：

- 扫描本地目录
- 领取待处理任务
- 调用应用内置的 FFmpeg / FFprobe
- 调用 ASR
- 清洗和保存文本
- 调用 AI
- 执行文件复制或移动
- 更新任务状态和事件记录

### 2.2 内置媒体工具

应用发布包必须携带当前目标平台的媒体工具：

```text
runtime/
└── ffmpeg/
    ├── windows-x64/
    │   ├── ffmpeg.exe
    │   └── ffprobe.exe
    ├── linux-x64/
    │   ├── ffmpeg
    │   └── ffprobe
    └── macos-arm64/
        ├── ffmpeg
        └── ffprobe
```

要求：

- 应用启动时检查内置 `ffmpeg` 和 `ffprobe` 是否存在且可执行。
- 媒体处理服务只能通过 `MediaToolchain` 获取工具路径，不能直接调用 `PATH` 中的命令。
- 开发环境允许通过配置显式指定外部 FFmpeg 路径，但生产发布包默认使用内置版本。
- 工具执行失败时保存版本、命令参数（隐藏敏感路径时按配置处理）、退出码和错误输出。
- 发布时记录 FFmpeg 版本和许可证信息，遵守 FFmpeg 及所选构建包的分发许可证。
- 不将 FFmpeg 二进制提交到源代码仓库，使用发布构建流程或安装包携带。

建议封装：

```python
class MediaToolchain:
    def ffmpeg_path(self) -> str:
        ...

    def ffprobe_path(self) -> str:
        ...

    def check(self) -> None:
        ...
```

### 2.3 不采用的方案

第一阶段不引入：

- Redis
- Celery
- RabbitMQ
- Kubernetes
- 独立微服务
- 云端对象存储

原因是系统是本地单用户工具，SQLite 加单 Worker 已经可以满足 MVP。未来需要多 Worker 或远程部署时，再把任务队列替换为 Redis/Celery，不改变业务接口。

### 2.4 Worker 并发策略

默认：

```text
1 个 Worker 进程
1 个 ASR 任务并发
1 个 AI 请求并发
```

原因：

- SenseVoice 可能占用较多内存或显存。
- 多任务并发容易造成 GPU 显存不足。
- 本地批处理优先保证稳定性。

并发数放入配置中，后续可以调整。

---

### 2.5 当前电脑的默认运行策略

当前开发电脑配置：

```text
CPU：AMD Ryzen 5 5600
内存：16 GB
显卡：NVIDIA GTX 1060 3 GB
```

默认运行策略：

```text
ASR 设备：CPU
Worker 并发：1
batch_size_s：30
VAD 单段最大时长：30000 ms
AI 分析：优先使用可配置的云端 API
```

原因：

- 3 GB 显存不适合作为 SenseVoiceSmall 的默认推理设备。
- R5 5600 可以承担单任务 CPU 转写。
- 16 GB 内存可以运行 FastAPI、Worker、FunASR 和 SQLite，但不建议同时处理多个 ASR 任务。
- 如果后续升级到 8 GB 以上显存，可以单独开启 GPU 配置并进行基准测试。

## 4. ASR 实现边界

### 4.1 三者关系

本项目不能把 `QwenAudio/SenseVoice` 和 FunASR 当作两个互斥选项：

```text
QwenAudio/SenseVoice
    = SenseVoice 官方代码、示例和模型说明

SenseVoiceSmall
    = 实际使用的语音识别模型

FunASR
    = Python 推理框架、VAD 和长音频处理能力
```

正式后端链路：

```text
内置 FFmpeg / FFprobe
    ↓
独立 SenseVoiceProvider
    ↓
FunASR AutoModel
    ↓
iic/SenseVoiceSmall
    +
fsmn-vad
    ↓
统一 ASRResult
```

官方参考：

- [QwenAudio/SenseVoice](https://github.com/QwenAudio/SenseVoice)
- [FunASR](https://github.com/modelscope/FunASR)
- [SenseVoice 中文说明](https://github.com/QwenAudio/SenseVoice/blob/main/README_zh.md)

### 4.2 `video_to_text.py` 的定位

保留 `video_to_text.py` 作为可独立运行的命令行参考工具，用于：

- 手工验证 SenseVoice 模型。
- 单文件转写调试。
- 验证 FFmpeg 和 ASR 参数。
- 作为后端正式实现的参考样例。

后端业务代码、Worker 和 ASR Provider **禁止导入或调用** `video_to_text.py`。该脚本与正式应用的任务状态、数据库、日志和配置保持独立。

### 4.3 后端正式实现

新增独立实现：

```text
app/services/asr/sensevoice_provider.py
```

该模块参考 `video_to_text.py` 的识别流程重新编写，但不复制 CLI 入口和控制台输出逻辑，职责包括：

- 加载 SenseVoice 和 FSMN-VAD。
- 接收 Worker 传入的音频路径和任务配置。
- 关闭模型内部 tqdm、`rtf_avg` 等非用户日志。
- 将 FunASR 返回值转换为统一的 `ASRResult`。
- 返回原始 JSON、完整文本和带时间戳分段。
- 抛出统一的 ASR 错误类型。

后端正式实现不得依赖 CLI 参数解析、CLI 输出预览或 CLI 的临时目录管理。

### 4.4 Provider 封装

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Any


@dataclass
class ASRResult:
    language: str | None
    text: str
    segments: list[dict[str, Any]]
    raw_result: list[dict[str, Any]]


class ASRProvider:
    def transcribe(
        self,
        audio_path: Path,
        language: str,
        options: dict[str, Any],
    ) -> ASRResult:
        raise NotImplementedError
```

`SenseVoiceProvider` 独立实现上述接口，并将 FunASR 结果转换为统一的 `ASRResult`。未来替换 Whisper、WhisperX、Paraformer 时，只新增 Provider，不修改任务编排。

## 5. 任务处理架构

### 5.1 任务来源

任务有三种来源：

```text
手动扫描目录
    ↓
扫描服务发现文件

手动选择单个文件
    ↓
任务 API 创建任务

定时/监听扫描
    ↓
扫描服务发现文件
```

### 5.2 Worker 主循环

```text
Worker 启动
    ↓
初始化 SQLite、FFmpeg、ASR 和 Provider
    ↓
定期执行目录扫描
    ↓
原子领取一个 QUEUED 任务
    ↓
按阶段执行任务
    ↓
每个阶段更新任务、进度和 task_event
    ↓
成功、失败或带警告结束
    ↓
继续领取下一个任务
```

### 5.3 任务阶段

```text
QUEUED
  ↓
PROBING             检查文件、读取媒体信息
  ↓
EXTRACTING          视频提取音频
  ↓
TRANSCRIBING        SenseVoice 语音识别
  ↓
POST_PROCESSING     文本清洗和分段
  ↓
SAVING              保存 TXT/JSON/SRT 和数据库结果
  ↓
ANALYZING           可选，调用 AI Provider
  ↓
TRANSFERRING        可选，复制或移动源文件
  ↓
COMPLETED
```

### 5.4 进度分配

进度不是来自 ASR 内部的 tqdm，而是由平台按阶段计算：

| 阶段 | 默认权重 |
|---|---:|
| 读取媒体信息 | 5% |
| 提取音频 | 15% |
| 语音识别 | 50% |
| 文本整理 | 10% |
| 保存结果 | 5% |
| AI 分析 | 10% |
| 文件转移 | 5% |

AI 关闭时，权重动态归一化。前端只显示：

```text
正在识别音频，请稍候
```

不显示 `rtf_avg`、tqdm 进度条等内部实现信息。

### 5.5 失败和重试

- 每个阶段捕获异常并转换为统一错误对象。
- 失败任务保存 `error_code`、`error_message`、`error_detail`。
- ASR 失败可以重试完整转写。
- AI 失败只重试 AI，不重新执行 ASR。
- 文件转移失败只重试转移，不重新执行转写。
- 重试保留原任务记录，并建立 `parent_task_id`。
- 应用重启后，超时的 `RUNNING` 任务恢复为 `QUEUED` 或 `FAILED`。

重试不覆盖历史：

```text
processing_task #100 失败
        │
        └── retry → processing_task #101
                         parent_task_id = 100
                         attempt_no = 2
```

页面按媒体文件聚合同一重试链，数据库保留每次执行的状态、事件、错误和结果版本。

```text
export_record
```

详细字段以《视频文案提取与 AI 内容分析平台——需求文档.md》的 SQLite 设计为准。

### 8.3 任务领取

Worker 领取任务时必须使用事务和状态条件，避免重复执行：

```sql
BEGIN IMMEDIATE;

UPDATE processing_task
SET status = 'RUNNING',
    current_stage = 'PROBING',
    started_at = :now,
    updated_at = :now
WHERE id = (
    SELECT id
    FROM processing_task
    WHERE status = 'QUEUED'
    ORDER BY created_at
    LIMIT 1
)
AND status = 'QUEUED';

COMMIT;
```

实际实现可以使用 SQLAlchemy，但必须保持同样的原子语义。

### 8.4 数据库事务边界

- 扫描发现文件和创建任务：一个事务。
- 领取任务和修改运行状态：一个短事务。
- 每次阶段完成后的状态、事件和结果记录：一个事务。
- FFmpeg、ASR、LLM 等耗时操作不能长时间占用数据库事务。
- 文件复制/移动完成后，再写入转移成功记录。
- Web 请求和 Worker 不共享长事务；模型推理、FFmpeg 和网络请求全部在事务外执行。

数据库连接建议启用：

```text
PRAGMA foreign_keys = ON
PRAGMA journal_mode = WAL
PRAGMA busy_timeout = 5000
```

Worker 使用 `heartbeat_at` 识别异常退出。只有心跳超过超时时间的 `RUNNING` 任务才允许恢复，避免正常处理时被重复领取。

## 15. 架构验收标准

1. 使用 Python 启动后端，不依赖 Java 服务。
2. 浏览器可以打开本地操作界面。
3. 用户可以在界面配置本地目录绝对路径。
4. 后端可以递归扫描目录中的视频和音频。
5. Worker 与 Web 请求进程分离，处理长视频时页面仍可操作。
6. Worker 使用独立编写的 `SenseVoiceProvider`，仅参考 `video_to_text.py`，不导入该脚本。
7. SQLite 保存媒体文件、任务、事件、转写和导出记录。
8. 页面可以看到任务状态、当前阶段、进度和错误信息。
9. 任务完成后可以查看原始文本、清洗文本和时间戳分段。
10. 任务失败可以重试，AI 和文件转移支持单独重试。
11. AI Provider、模型、Base URL 和 Prompt 可以在设置中修改。
12. 更换 OpenAI Compatible 模型不需要修改任务编排代码。
13. 文件复制或移动有校验和历史记录。
14. 控制台和页面不显示难以理解的 ASR 内部进度条。
15. 应用重启后任务记录和处理结果仍然存在。
16. 重试会生成新的 `processing_task`，历史失败记录保持不变。
17. Worker 心跳超时后可以恢复任务，正常运行任务不会被重复领取。
18. 控制台每个阶段最多输出少量人话日志，不出现动态进度条。
